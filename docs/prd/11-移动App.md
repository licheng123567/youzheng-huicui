## 1. 定位与边界

### 1.1 定位

**催收员（CO）单角色作业 App**。核心 = 「拨号跳转 + 读系统录音目录 + 自动上传」三件事（TD-1 机制A），围绕它补齐 CO 的移动作业闭环：工作台待办 → 案件（私海/公海抢单）→ 拨号催收 → 录音自动回填 → 跟进/承诺/缴费链接/工单 → 消息回流。App 是"催收员的手"，**不是 Web 的移动镜像**——只搬 CO 高频作业动作，管理/配置/报表一律留在 Web。

| App 负责 | 服务端负责（复用现有契约） |
|---|---|
| 选案件→跳系统拨号器、记录通话元数据 | ASR 解析、分钟扣减（BR-M5-01/02） |
| 监听/捕获系统录音文件、录音↔案件匹配 | 话术抽取、风控质检、飞轮（M5） |
| 上传队列（重试/离线/去重） | 转写存储、计费、解析状态查询 |
| 机型自检、首登引导 | 机型白名单矩阵维护（后台） |

### 1.2 明确不做的（及理由）

| 不做 | 理由 |
|---|---|
| **iOS 首版** | **iOS 沙盒禁止任何第三方应用读取/录制系统通话音频**（无系统通话录音目录、CallKit 不暴露通话音频流），核心闭环"读系统录音目录"在 iOS 上物理不成立——这正是选 Android 的根因。iOS 若做只剩"手动上传"残缺体验，投入产出不成立；CO 用 iPhone 者走 Web 手动上传救济（BR-M4-01b） |
| 管理角色功能（VL/PL/SA/SE） | 派单、分配、对账、报表、参数配置均为桌面密度作业，留 Web（UI 总纲 §7 三端形态） |
| 物业协调员（PC）功能 | 送达签收拍照等 PC 移动场景**后置为二期**（原型 app.html 已有交互设计，但首版收敛 CO 单角色以保工期）；PC 本期走 Web |
| 系统/软电话主动外呼 | 已定不做（OQ-M4-2 收敛）：系统不主动拨号、不感知拨打时机，通话在手机本机进行（BR-M4-01b） |
| 通话中实时提示 | 已定不做（OQ-M5-1）：无通话中链路，AI 策略只在通话前+解析后两个时点 |
| App 内自录音（MediaRecorder） | AOSP 限制第三方录不到对方声音，且碎片化严重；走读系统录音目录（TD-1 机制A） |
| 结案/撤案/坏账操作 | CO 不能结案（BR-M4-05），App 无此入口 |
| 在线缴费 | M7 后期延伸，App 仅发链接（BR-M4-19） |

### 1.3 厂商自带通话录音能力矩阵（选 Android 的支撑）

国内主流 OEM ROM 在**系统层**提供"自动通话录音"，可录到双方声音（已实验验证，TD-1）；这是机制A 的地基。

| 厂商/ROM | 自动通话录音 | 系统设置入口（典型） | 备注 |
|---|---|---|---|
| 华为 EMUI / HarmonyOS | ✅（可全局自动） | 拨号盘 → 设置 → 通话自动录音 | ⚠️ 部分版本录音为专有格式，须自检验证可解析性（附录A A.6 第3步） |
| 荣耀 MagicOS | ✅ | 同华为系 | 分家后目录/格式可能漂移，按矩阵实测 |
| 小米/红米 MIUI / HyperOS | ✅（可全局自动/指定号码） | 电话 → 设置 → 通话录音 | 文件名含号码，匹配友好 |
| OPPO/一加/realme ColorOS | ✅ | 电话 → 设置 → 通话录音 | |
| vivo/iQOO OriginOS | ✅ | 电话 → 设置 → 通话录音 | |
| 三星 OneUI（国行） | ✅（部分区域版本） | 电话 → 设置 → 录制通话 | 海外版多被禁用，国行可用 |
| 原生类（Pixel/AOSP） | ❌ | — | 白名单外，机制A 固有边界，走 Web 手动上传救济 |

> 结论：**目标机型 = 国内 OEM 白名单机型**；白名单矩阵（机型+ROM版本+目录+文件名规则+格式可解析性+是否验证）由后台维护、App 启动自检增量上报（§3.6）。

## 2. 核心闭环用户旅程

```
登录(口令/短信/多账号) → 今日工作台(PROMISE_DUE/RELEASE_WARN/TICKET_RECEIPT/NEW_ASSIGNED)
  → 案件列表(我的持有 / 本商公海抢单 / 开放池抢单)
  → 案件详情作业台(业主/欠费/时间线/通话前策略)
    → 点号码 → 跳系统拨号器(ACTION_CALL) → 本机通话(系统自动录音)
    → 通话结束(IDLE) → App 检测录音目录新文件 → 号码+时间窗匹配案件
    → 自动入上传队列 → multipart 上传 → 服务端 ASR 异步解析
    → 「获取最新通话录音」查状态(无录音/上传中/解析中/已就绪 BR-M4-01b)
    → 已就绪 → AI 复盘(对话气泡+风险+下一步建议) → 通话结果标记(BR-M4-03a)
  → 跟进手记 / 登记承诺(单笔/分期) / 发缴费链接(短信/转微信) / 转工单 / 建议法务
  → 消息中心(工单回执/线下回款/律师函进展回流 BR-M4-23)
```

### 2.2 本模块业务规则（BR-APP-xx）

- **BR-APP-01（单角色收敛）**：App 仅面向 CO 角色开放作业功能。非 CO 账号登录时提示"请使用网页端"，不渲染作业界面（多账号手机号下选中 CO 账号方可进入）。
- **BR-APP-02（契约零新增默认）**：App 一切服务端交互复用 openapi-core.yaml 既有端点与 `x-permission` 权限点；界面操作按 `GET /me` 返回的 permissions 集合门控（与 Web 同一套权限字典，BR-M1-03）。
- **BR-APP-03（拨号即建会话）**：点号码拨打前，App 本地生成 callId 会话记录 `{callId, caseId, number, dialStartTs}` 并持久化（Room）；这是录音↔案件匹配的锚点（§3.3）。**系统不主动拨号、不感知拨打时机**的边界不变（BR-M4-01b）。
- **BR-APP-04（自动上传 + 手动救济双通道）**：通话结束检测到录音 → 自动上传（source=APP_AUTO）；检测超时/无文件 → 界面提示并提供"手动选择录音文件上传"（source=MANUAL），走同一解析链路；两条通道都不通 → 引导 Web 手动上传（BR-M4-01b 救济）。
- **BR-APP-05（未接通不上传）**：CALL_LOG duration≈0 且无录音文件 → 判定未接通，仅生成本地通话记录供标注参考，**不上传**（未接通类标注不重置 T_collector，BR-M4-03）。
- **BR-APP-06（离线暂存 + 恢复同步）**：跟进/承诺/结果标记等写操作在离线/弱网时本地排队，恢复网络后按序自动同步（OQ-M4-1 已定）；同步冲突以服务端为准、本地提示。
- **BR-APP-07（上传队列可见可管）**：上传队列（待上传/上传中/失败重试/已完成）对用户可见，可手动重试/删除失败项；上传成功后本地录音按策略清理（默认保留 7 天，可配）。
- **BR-APP-08（机型自检门禁）**：启动自检不通过（无自动录音能力/目录不可读/格式不可解析）→ 显著提示"本机型无法自动回传录音"，作业功能可用但录音回传降级为手动/Web 救济；自检结果上报后台白名单矩阵（§7 提案）。
- **BR-APP-09（推送与轮询兜底）**：承诺到期/释放预警/工单回执等提醒经"工作台待办 + App 推送"（BR-M4-13）；首版推送通道未就绪时以"前台轮询 `notifications/unread-count` + 进前台刷新"兜底，不阻塞里程碑。

## 3. 录音管线规格（重中之重）

> 本节将 BR-M4-01b/01c 与技术选型附录A 收敛为可验收规格。App 端状态机：`待拨打 → 拨号中 → 通话中(OFFHOOK) → 通话结束(IDLE) → {未接通 | 待匹配 → 已匹配 → 待上传 → 上传中 → 已上传 → 解析中 → 已就绪/失败}`。

### 3.1 分机型录音目录预设表

> ⚠️ 路径随 ROM 大版本漂移，本表为**首发预设候选集**（按优先级探测），真值以**后台白名单矩阵实测**为准并可远程下发更新（BR-APP-08）；用户可手动改路径+重新检测（BR-M4-01c）。

| 厂商/ROM | 候选目录（`/storage/emulated/0/` 下，按优先级） | 典型文件名模式 | 格式 |
|---|---|---|---|
| 华为 EMUI/HarmonyOS | `Sounds/CallRecord/`；旧版 `record/`、`Record/` | `联系人或号码_日期时间.m4a`（如 `13800138000_20260709103000.m4a`） | m4a（⚠️ 部分版本专有封装，自检验证） |
| 荣耀 MagicOS | 同华为系 `Sounds/CallRecord/` | 同华为 | m4a |
| 小米/红米 MIUI/HyperOS | `MIUI/sound_recorder/call_rec/`；HyperOS 部分 `Recordings/call_rec/` | `通话录音_联系人(号码)_时间戳.mp3` | mp3/aac |
| OPPO/一加/realme ColorOS | `Music/Recordings/Call Recordings/`；旧版 `Recordings/`、`Record/PhoneRecord/` | `号码_时间戳.mp3` 或 `联系人-号码-日期.amr` | mp3/amr/wav |
| vivo/iQOO OriginOS | `Record/Call/`；部分 `录音/通话录音/` | `号码(联系人)_日期.wav` | wav/mp3 |
| 三星 OneUI（国行） | `Recordings/Call/`；旧版 `Sounds/` | `通话录音 号码_日期.m4a` | m4a |
| 通用兜底 | `Recordings/`、`Music/Recordings/`、`Record/`、`Sounds/` 全量候选扫描 | 按"时间窗+号码归一化"匹配（不依赖文件名） | — |

### 3.2 新文件检测策略（三层）

| 层 | 机制 | 触发时机 | 说明 |
|---|---|---|---|
| 主 | `FileObserver` 监听录音目录，事件 `CLOSE_WRITE` + `MOVED_TO` | 通话结束（IDLE）即起监听，窗口 = 通话结束后 120s（可配） | 部分 ROM 先写临时文件再重命名，故须听 MOVED_TO；事件后轮询文件大小连续 N 秒（默认3s）不变才入队，防半截文件 |
| 辅 | `MediaStore` ContentObserver（audio 集合变更） | 与主层并行 | Scoped Storage 下部分 ROM 录音走 MediaStore 落库，作交叉信号 |
| 兜底 | 目录增量扫描（对比 lastModified > 上次扫描点） | ①App 进前台；②通话结束后 FileObserver 超时未命中；③WorkManager 周期任务（默认 30min，仅充电/省电豁免下运行，节制电量） | 覆盖 FileObserver 被 ROM 杀死/事件丢失场景 |

- 后台存活：前台服务（含常驻通知）仅在"通话结束→匹配→上传"窗口期拉起；引导电池优化豁免（附录A A.7）。**不做 7×24 常驻监听**（电量与商店审核双不利）。

### 3.3 通话-案件匹配规则

1. **锚点**：拨号前落库的本地会话 `{callId, caseId, number, dialStartTs}`（BR-APP-03）；通话结束补 `callEndTs`。
2. **主匹配**：候选录音文件满足——①文件 `lastModified`（或文件名解析出的时间）∈ `[dialStartTs, callEndTs + buffer(默认60s)]`；②文件名解析出的号码与 `number` **归一化一致**（去 +86/空格/横线）。两条件取交集。
3. **退化**：文件名无号码（ROM 差异）→ 仅按时间窗匹配；时间窗内多个候选 → 取时间就近者；连续拨打多案 → 按各 callId 时间窗就近分配，冲突时进"待人工确认"态（App 内让 CO 二选一，宁可问不可错挂案件）。
4. **接通/时长判定**（三信号交叉，附录A A.5a）：主信号 = `READ_CALL_LOG` 查 `CallLog.Calls`（OUTGOING+号码+date≈dialStartTs）取 duration；辅信号 = TelephonyCallback OFFHOOK/IDLE；服务端 VAD 再交叉验证。duration>0 且有录音 → 上传并携带 `recordedAt/durationSec/phone` 元数据。

### 3.4 上传策略

| 项 | 规格 |
|---|---|
| 队列 | Room 表 `{callId, caseId, filePath, fileHash, status, retryCount, createTs}`，进程被杀/重启可恢复 |
| 执行 | WorkManager 网络约束任务 + 上传期前台服务；`POST /cases/{id}/recordings` multipart（file + source/recordedAt/durationSec/phone），携带 `Idempotency-Key = fileHash`（契约已支持幂等键，409=已上传视为成功） |
| 网络开关 | 设置项「仅 WiFi 上传」默认关（催收时效优先，录音单文件通常 <10MB）；开启时流量下入队不发、WiFi 下自动 flush |
| 失败重试 | 指数退避（1/2/4/8…min，封顶 30min），最多 N 次后转"失败待手动"，队列页可一键重试 |
| 断点 | 首版**整文件重传**（文件小，幂等键防重复计费/重复解析）；分片断点续传列 §7 增量提案（仅当实测出现大文件/极弱网证据再启动） |
| 去重 | 本地 fileHash 判重 + 服务端幂等键判重，双保险 |
| 清理 | 上传成功且状态达 READY 后，本地文件保留 7 天（可配）删除；本地录音副本落 App 私有目录并加密 |

### 3.5 首登引导流程（落地 BR-M4-01c）

四步向导，全部通过才进工作台（可跳过但持续角标提醒）：

| 步 | 内容 | 通过判据 |
|---|---|---|
| ① 权限申请 | CALL_PHONE / READ_CALL_LOG / READ_PHONE_STATE / 存储（MANAGE_EXTERNAL_STORAGE 或目录授权）/ 通知，逐项说明用途（合规要求） | 全部授予 |
| ② 开启系统自动通话录音 | 识别机型 → 展示**该厂商图文指引**（§1.3 设置入口）→ 深链跳系统设置（能跳则跳） | 用户确认已开启 |
| ③ 录音目录确认 | 按 §3.1 预设候选探测既有录音文件 → 命中则锁定目录；未命中 → 手动选目录 + 重新检测 | 目录可读且含（或产出）录音文件 |
| ④ 测试通话校验 | 引导拨一通测试电话（如自己另一号码）→ 走完整"检测→匹配→上传→解析"链路 → 服务端验证可解析+双说话人 | 测试录音状态达 READY |

- 引导结果（机型/ROM/Android版本/目录/各步结果）上报后台白名单矩阵（§7 提案）；④失败 → 提示手动上传救济 + 换推荐机型建议（BR-APP-08）。

### 3.6 机型自检（启动 + 定期）

复用附录A A.6 六步：权限自检 → ROM 能力探测（白名单命中/测试拨号）→ 录音可解析性验证 → 双向音验证 → 上报 → 通过/引导。白名单矩阵支持远程下发（目录/文件名规则热更新，不发版）。

## 4. 权限与合规

### 4.1 Android 运行时权限清单

| 权限 | 用途 | 申请时机 | 拒绝时降级 |
|---|---|---|---|
| `CALL_PHONE` | ACTION_CALL 直接拨出（不手输号码） | 首登引导① | 降级 ACTION_DIAL（跳拨号盘需手按拨出） |
| `READ_PHONE_STATE` | TelephonyCallback 通话起止 | 首登引导① | 无通话结束信号，仅靠进前台扫描 |
| `READ_CALL_LOG` | 接通/时长判定主信号 | 首登引导① | 接通判定退化为"有无录音文件" |
| `MANAGE_EXTERNAL_STORAGE`（Android 11+）或 SAF 目录授权 | 读系统录音目录 | 首登引导③ | **核心功能不可用**，强引导；仅手动上传 |
| `POST_NOTIFICATIONS`（13+）+ `FOREGROUND_SERVICE(_DATA_SYNC)` | 上传前台服务与提醒 | 首登引导① | 上传仅在前台进行 |
| 电池优化豁免（引导型，非权限） | 防国产 ROM 杀上传/监听进程 | 首登引导后弱引导 | 依赖进前台补扫兜底 |

### 4.2 分发与商店审核约束（决策）

| 渠道 | 约束 | 决策 |
|---|---|---|
| Google Play | `MANAGE_EXTERNAL_STORAGE` 与 `READ_CALL_LOG` 均属敏感权限，通话录音类用途**基本必被拒** | **不上架**（目标用户在国内，无损失） |
| 国内商店（华为/小米/OPPO/vivo/应用宝） | 对"读取通话记录/全盘存储"审核趋严，需软件著作权+隐私政策+权限用途说明；"催收"类目本身敏感，存在拒审风险 | **首版不依赖商店**：B2B **企业侧载分发**（官网/内部渠道下载 APK + App 内置升级检查）；商店上架二期按需评估，届时可做"目录授权（SAF）替代 MANAGE_EXTERNAL_STORAGE"的合规变体 |
| App 内置升级 | 自建版本检查 + APK 下载安装（REQUEST_INSTALL_PACKAGES） | 首版必做（无商店渠道时的唯一更新通路） |

### 4.3 录音告知与隐私合规（BR-M5-09 承接）

| 项 | 要求 |
|---|---|
| 通话录音告知义务 | 催收话术模板/作战手册内置录音告知提示语（"本次通话将录音"）；培训与质检（M5 风险检测）双重约束；物业↔业主合同层加录音授权条款（技术选型§合规） |
| 双录合规（催收行业） | 全量录音+转写留存（BR-M4-08/M5-07 全量质检），录音与转写归属案件、按 M1 隔离与 M8 结案收敛控可见；风险话术（辱骂/威胁/违规承诺）自动检出告警——App 是采集端，合规主体在平台质检链路 |
| 隐私政策 | App 首启弹隐私政策（明示：读取通话记录/录音文件的目的、范围、存储期限），逐项权限用途说明；不采集与作业无关的个人信息；不读取非匹配窗口内的录音文件 |
| 本地数据 | 录音副本加密存储（App 私有目录）、上传后限期清理（§3.4）；业主号码等敏感字段不落非必要日志 |
| 数据归属 | 录音/转写语料归平台（护城河前提，技术选型§合规）；App 不留长期明文副本 |

## 5. 非功能需求

| 类 | 要求 |
|---|---|
| 离线容忍 | 案件列表/详情本地缓存（进入过即缓存，标注数据时间）；写操作（跟进/承诺/标记）离线排队、恢复自动同步（BR-APP-06）；录音上传天然离线队列（§3.4） |
| 弱网 | 请求超时 10s + 重试；列表增量分页；图片附件压缩后上传；上传失败不阻塞作业流 |
| 电量 | 无 7×24 常驻监听；FileObserver 仅通话结束窗口期活跃；周期扫描默认 30min 且尊重 Doze；前台服务仅上传期存活 |
| 性能 | 冷启动 ≤2s（中端机）；列表 60fps；单案详情聚合端点一次取齐（`GET /cases/{id}`），避免瀑布请求 |
| 安全 | token 存 EncryptedSharedPreferences（Keystore 加密）；TLS + 证书固定（certificate pinning，防抓包窃取业主数据）；截屏水印（账号名+时间，防泄露溯源）**可选项默认开**；越狱/root 检测仅提示不阻断 |
| 会话 | token 过期 401 → 静默跳登录页（保留未同步队列不丢）；多账号切换不清上传队列（队列按账号隔离） |
| 可观测 | 客户端埋点：自检结果、录音检测命中率、匹配成功率、上传成功率、端到端时延（通话结束→READY）——这是 M-A4 机型适配验收的数据来源 |

## 8. 里程碑（数周级分解）

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| **M-A1 骨架+登录+案件读**（约1.5周） | 工程骨架（网络层=openapi-generator 生成客户端/Room/WorkManager 基建）；登录三态（密码/短信/多账号选择）；工作台（cockpit 待办）；案件列表（私海/公海Tab，公海脱敏展示）；案件详情只读（聚合端点渲染）；消息中心列表 | ①三种登录路径真机走通含 401/限流分支；②CO 登录见待办四类且点击直达案件；③公海未持有案件号码脱敏（BR-M3-21a）；④断网进入已缓存案件可读 |

| **M-A3 作业写操作+消息闭环**（约1.5周） | 抢单/释放（选原因）；跟进手记（附件）；承诺（单笔/分期）；AI 复盘（气泡+建议卡采纳联动）+通话结果标记；缴费链接（发/重发/作废/我的链接）；转工单/建议法务；号码管理；离线写队列；录音回放（C1）；我的（业绩/结算/设置/上传队列管理） | ①CO 全套作业动作与 Web 数据互通（BR-M4-09：App 写、Web 即见，反之亦然）；②抢单并发另一端得 409 提示；③离线打标注，恢复网络自动同步成功；④发短信链接命中冷却时正确提示（409 BIZ_SMS_COOLDOWN）；⑤复盘内标记接通类结果后 T_collector 重置（服务端验证） |
| **M-A4 机型适配矩阵实测+灰度**（约1-2周） | 机型矩阵实测（≥6 厂商×主流 ROM 版本，含华为格式可解析性）；白名单后台数据灌入+远程下发验证；电量/存活专项（省电模式过夜）；埋点看板（检测命中率/匹配成功率/上传成功率/端到端时延）；内置升级通道；灰度=1-2 家服务商真实作业 | ①矩阵表逐机型有"目录/文件名/格式/双向音/结论"五项实测记录；②灰度期录音自动回传成功率 ≥90%（白名单机型内），失败均有显式提示非静默丢；③省电模式下过夜后拨打，录音仍能在进前台后补传；④升级通道发一次真实版本验证 |
